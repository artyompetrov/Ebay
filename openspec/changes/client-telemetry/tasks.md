# Tasks

The change ships in two PRs. Stage 1 (groups 1-6): backend relay, removal of client error storage and the Chrome extension. Stage 2 (groups 7-8): the Blazor frontend. The change stays active between the stages and is archived after stage 2; until then the coverage checker defers the requirements this change touches.

Verify: unit tests (`[TestOf]` per class) with a stub handler cover success, `4xx`, `5xx`, network failure and the default/configured level.

Filter the relay's HttpClient logs, check the hosting log level for relay requests, and filter them by path if they are Information. Verify:
  - Integration tests replace the relay client's primary handler with a fake collector in `ConfigureServices` and carry `[OpenSpecScenario("client-telemetry", ...)]` for all scenarios of "Backend relays client telemetry to the collector", "Telemetry relay accepts only authenticated, bounded requests" (including the chunked 1 MiB + 1 case: nothing forwarded) and "Backend serves the client telemetry level".
  - `TracedRequestFilterTests` plus an integration test tagged `observability-tracing` / "Telemetry relay is not traced" (no server span and no collector client span) pass.
- [x] 1.4 Remove the `debug` exporter from `deploy/config/otelcollector/config.yaml` (from the logs pipeline and its definition; drop the now-stale comment in the traces pipeline).
